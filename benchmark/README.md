## 题型说明

### 1. 事实型题目
验证系统**精确提取单一事实**的能力。

**特点**：
- 问题聚焦于单一事实点
- 答案为明确的短文本（姓名、日期、数值等）
- 可从原文中直接定位

**示例**：
> **问题**：犯罪嫌疑人的血液酒精浓度是多少？
> **答案**：202mg/100ml

### 2. 证据集合型题目
验证系统**从多处证据聚合信息**的能力。

**特点**：
- 问题需要整合多个事实点
- 答案为列表或组合信息
- 需要理解证据间的关联

**示例**：
> **问题**：认定犯罪事实的证据有哪些？
> **答案**：供述材料、司法鉴定报告、查获经过、户籍证明、其他材料

### 3. 冲突缺口型题目
验证系统**识别信息缺失**的能力，避免幻觉。

**特点**：
- 问题看似合理但文书无答案
- 正确答案应为"材料未显示"
- 用于测试系统的诚实性和边界识别

**示例**：
> **问题**：曾庆成具体喝了什么酒？
> **答案**：材料未显示

## 添加新案件

### 步骤

1. **创建目录结构**
   ```bash
   mkdir -p benchmark/{文书类型}/{案件名称}/原始数据
   ```

2. **添加原始数据**
   将原始文书或解析结果放入 `原始数据/` 目录

3. **创建题目文件**
   - `01-事实型题目.md` - 10题左右
   - `02-证据集合型题目.md` - 5题左右
   - `03-冲突缺口型题目.md` - 5题左右

4. **创建案件 README.md**
   包含案件摘要、关键事实清单、题目统计

5. **更新本文件**
   在题库总览表中添加新案件信息

### 题目格式规范

```markdown
## {序号}. {题目标题}

**问题**：具体问题内容？

**答案**：标准答案

**位置**：文书中的位置描述
**证据原文**：`原文摘录`
```

## 验证方法

### 1. 格式检查
```bash
# 验证题目数量
grep -c "^## " benchmark/起诉意见书/曾庆成危险驾驶案/*.md

# 验证问题格式
grep "^\*\*问题\*\*" benchmark/**/*.md | wc -l
```

### 2. 答案验证
- 确保事实型答案与原始数据一致
- 确保证据集合型答案完整无遗漏
- 确保冲突缺口型问题确实在文书中无答案

### 3. 数值落地
- 数值类答案必须有原文支撑
- 在证据原文中标注出处

## 使用场景

### PR3 Answer Gate 验证
本题为 PR3（引用校验功能）设计，用于验证：
1. 系统能否准确定位答案的原文出处
2. 系统能否识别答案是否真实存在于文档中
3. 系统能否拒绝回答文档中不存在的信息

### RAG 系统评估
- **召回率**：事实型题目的答案命中率
- **精确率**：引用位置的准确度
- **诚实性**：冲突缺口型题目的正确拒绝率
